# Roadmap

## Initial implementation

- CSV profiling and validated local uploads.
- Binary classification: majority baseline, logistic regression, random forest.
- Regression: median baseline, ridge, random forest.
- Temporal holdouts and training-label availability checks.
- Daily-count forecasting: lag-7 baseline and lag-feature ridge; exploratory bands.
- K-means profiles and Isolation Forest unusual-record scores.
- Document chunking, lexical retrieval, source excerpts and deterministic evidence reports.
- Optional LangGraph orchestration and explicitly configured LangChain provider synthesis.
- Append-only experiment records with data fingerprints.
- Local API, project page, replay snapshot, Docker configuration and CI tests.
- Real Olist adapter and full delivered-cohort baseline comparison, including unsuccessful learned-model results.
- Public Olist workspace with portable numeric inference, all-status historical forecasting, review rating-group classification and browser evidence reports.
- Genuine browser sample comparisons with baselines, ridge/logistic regression and bounded random forests in a background worker; separate sample/full-data reports.

## Next milestones

The v0.4 generation extension executes a hosted pretrained Llama model and publishes 24 actual calls plus 12 reused validation decisions. It includes owner-reviewed question/source labels, bounded evidence retrieval, structural citation checks, unsupported-query cases and measured binding latency. This is model integration and evaluation, not transformer training. Next, manually review the generated claims, add independently authored questions and evaluate the two false refusals on a fresh development suite.

The v0.3 research extension adds a retrospective word/character review-classification ablation, per-class errors, a repeated-wording audit and group-bootstrap intervals. It also measures lexical/E5 dense/RRF retrieval on 40 AI-authored seed questions in 20 bilingual category pairs, with an opt-in browser encoder and runtime compatibility checks. The technical walkthrough includes reproduction steps and exercises for independent practice. These are completed implementations; independent human relevance review and external validation are still outstanding.

1. Investigate the weak neutral-rating class and delivery-model failures. Use separate development periods and document the retrospective status of any already inspected test data; acquire a genuinely new evaluation period or dataset for confirmation.
2. Have the project owner independently audit the seed retrieval labels and extend them with realistic questions written before inspecting rankings. Diagnose Portuguese-language failures and hybrid false acceptance. Evaluate any future reranker against the declared baselines.
3. Broaden temporal validation and bounded hyperparameter search within training/validation data, followed by a new frozen evaluation. Preserve unsuccessful experiments.
4. Exportable trained pipelines and validated record-level prediction endpoints.
5. Compare the implemented TF-IDF review rating-group classifier with a fine-tuned multilingual transformer.
6. MLflow experiment integration, drift analysis and monitoring beyond the existing local run log.
7. Recommendation experiments on a suitable repeated-interaction dataset, evaluated chronologically.
8. OCR, document extraction, multimodal search and MCP tools with independent benchmarks.

Optional dependencies, planned capabilities and configuration files are not evidence that an integration has been exercised. Record the actual experiment, data source, evaluation, failure cases and cost before making a resume claim.
